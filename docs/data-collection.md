# データ収集の方針

このツールは、便や尿を識別するモデルを持っていません。将来、排泄の前の姿勢や動作を予測したり、排泄物を識別して確定の通知を出したりするには、実際の映像と正解のラベルが必要です。ここでは、そのためのデータの集め方をまとめます。

## 集める動画

排泄の動画だけでなく、食事・座る・伏せる・匂いを嗅ぐ・通過する動画も保存し、動画 GUI でラベルを付けてください。排泄以外の場面がないと、誤検知を評価できません。

- 開始/完了は分かる範囲で指定し、映っていない部分を推測で埋めないでください。
- 切断等がある部分動画は明示的に区別し、時刻が不確かな部分を予測の正解データに使わないでください。

動画の保存とラベル付けの操作は [動画](video.md) を参照してください。

## 評価のしかた

近い時刻の重複クリップを学習用と評価用に分けると結果を過大評価するため、別の日・別イベントで評価します。

## まだできていないこと

学習済みモデルによる姿勢判定・排泄開始前の予測・排泄物識別による確定通知は未実装です。
実動画が集まったら、排泄中の動作分類を別日の動画で評価します。
モデル精度、誤通知/日、見逃し、通知が実際の開始より何秒早かったかを測ってから通知へ接続します。

保存動画の旋回候補の分析（`circling-review`）は、前兆の予測に向けた最初の試みです。[犬の検出](dog.md#保存動画から旋回候補を確認する) を参照してください。

## 保存済みの録画で判定器を比較する

動画 GUI で排便、排尿、両方、排泄なしを確認した録画の ID を集め、評価セットを JSON で作ります。録画 ID は動画詳細ページの URL の `id` にあります。1回の評価には同じ検知範囲と基準で撮影した録画を選びます。過去の基準で撮った録画を評価する場合は、`--scene` に当時の ROI と基準画像の保存先を指定します。

```json
{
  "clips": [
    {"id": "録画のID", "event": "排泄や滞在を区別する名前", "tags": ["夜間", "メッシュ付き"]},
    {"id": "別の録画のID", "tags": ["通過"]}
  ]
}
```

`event` と `tags` は任意です。同じ出来事の録画は1本を選んでください。台帳上の同じイベントや、同じ `event` を指定した録画の重複は検出します。判定不能や未ラベルの録画は正解の集計から外れます。録画の一部欠落は自動でタグになります。

```bash
uv run poop-detector video-benchmark \
  --dataset data/evaluation.json \
  --judge codex:利用するモデル名 \
  --judge claude:利用するモデル名 \
  --judge gemini:利用するモデル名 \
  --output data/evaluation-result.json \
  --send-images
```

`--send-images` を指定すると、同じ抽出画像と判定指示を選んだ提供元に送ります。認証方法は[判定器とモデルを選ぶ](video.md#判定器とモデルを選ぶ)を参照してください。テストの通知は送信せず、運用中の判定や正解ラベルは更新しません。

端末に排便・排尿ごとの適合率と再現率が表示されます。JSON では「両方」「排泄なし」を含む取り違え、判定不能とエラーの件数、条件ごとの集計、動画ごとの判定を確認できます。「両方」は排便と排尿の双方に含まれます。再現率の分母は判定不能やエラーになった動画も含む全正解陽性です。適合率の分母はその種類を検出したと判定した件数です。分母が0の指標は JSON で `null` になります。
