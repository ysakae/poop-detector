# データ収集の方針

このツールは、便や尿を識別するモデルを持っていません。将来、排泄の前の姿勢や動作を予測したり、排泄物を識別して確定の通知を出したりするには、実際の映像と正解のラベルが必要です。ここでは、そのためのデータの集め方をまとめます。

## 集める動画

排泄の動画だけでなく、食事・座る・伏せる・匂いを嗅ぐ・通過する動画も保存し、動画 GUI でラベルを付けてください。排泄以外の場面がないと、誤検知を評価できません。

- 開始/完了は分かる範囲で指定し、映っていない部分を推測で埋めないでください。
- 切断等がある部分動画は明示的に区別し、時刻が不確かな部分を予測の正解データに使わないでください。

動画の保存とラベル付けの操作は [動画](video.md) を参照してください。

## 評価のしかた

近い時刻の重複クリップを学習用と評価用に分けると結果を過大評価するため、別の日・別イベントで評価します。

## まだできていないこと

学習済みモデルによる姿勢判定・排泄開始前の予測・排泄物識別による確定通知は未実装です。
実動画が集まったら、排泄中の動作分類を別日の動画で評価します。
モデル精度、誤通知/日、見逃し、通知が実際の開始より何秒早かったかを測ってから通知へ接続します。

保存動画の旋回候補の分析（`circling-review`）は、前兆の予測に向けた最初の試みです。[犬の検出](dog.md#保存動画から旋回候補を確認する) を参照してください。

## 保存済みの録画で判定器を比較する

Codex CLI・Claude Code CLI・Antigravity CLI などの判定器を、人が確認した同じ録画で比べます。手順は、録画を集めてラベルを付ける、評価セットの下書きを作る、条件のタグを確かめて版を固定する、比較する、結果を見る、の順です。評価セットの作成・確認・固定は画像を外部に送りません。送るのは比較（`--send-images`）だけです。

### 1. 録画を集めてラベルを付ける

動画 GUI で、排便・排尿・両方・排泄なしのラベルを付けます。自動通知のあった録画だけでなく、犬の入退場（`dog_enter`・`dog_exit`）や手動保存の録画も確認してください。排泄なしには、食事・匂い嗅ぎ・旋回・休息・通過など、誤検知しやすい場面を含め、動作も選びます。昼間と夜間（赤外線）、メッシュ付きトレー、トレー内とトレー外、遮蔽、既存の跡と新しい排泄が同居する場面も集めます。

- 映像だけでは確定できない録画は「判断できない」で保存します。評価セットでは判定不能として数え、精度の集計から外します。
- 判定器の判定は正解として使いません。正解は人が付けたラベルだけです。
- 人が気づいた見逃しは `missed` か GUI の目視の記録で残します。評価セットは、見逃しの前後30秒に録画があるものとないものを分けて数えます。録画のない見逃しは、録画に対する判定精度ではなく、録画の開始を含む監視全体の取りこぼしです。

### 2. 評価セットの下書きを作る

```bash
uv run poop-detector benchmark-dataset create --name evaluation --final-since 2026-11-01
```

保存済みでラベルのある録画から下書きを `data/benchmarks/datasets/evaluation-draft.json` に作り、種類×分割・条件ごとの件数を表示します。件数の少ない場面は、追加の収集が必要です。

- 同じイベントやひも付く確定記録が同じ録画、30秒以内に重なる録画は、同じ出来事の重複として1本にまとめます。残すのは、排泄を確認したもの、排泄なし、判定不能の順で、長い録画です。重複は `duplicates` に残ります。
- `--final-since` の日（ローカル時刻）以降の録画を最終評価用（`final`）、それより前を調整用（`tuning`）にします。近い時刻の録画が両方に入らないよう、日付で分けます。省くとすべて調整用です。
- `--since`・`--until` で録画の期間を絞れます。
- 録画の一部欠落は「一部欠落」、トレー外の排泄は「トレー外」のタグが自動で付きます。
- 録画ごとに撮影時の画角（ROI と基準画像の署名）を記録します。データの保存先と、トレー交換で残した `tray-scenes/` の下の登録は自動で探します。ほかに保存した過去の ROI と基準画像は `--scene 場所` で渡します（複数指定可）。
- 既存の手書きの評価セットや下書きの `tags`・`event`・`exclude` を引き継ぐには `--base 既存のJSON` を付けます。

### 3. 条件を確かめて版を固定する

下書きの各録画の `tags` に「夜間」「メッシュ付き」「遮蔽」などの条件を書き足し、使わない録画は `"exclude": true` にします。`event` を同じ値にした録画は、同じ出来事の重複として固定を断ります。

```bash
uv run poop-detector benchmark-dataset check data/benchmarks/datasets/evaluation-draft.json
uv run poop-detector benchmark-dataset freeze data/benchmarks/datasets/evaluation-draft.json --version 1
```

`check` は、件数と、録画が見つからない・台帳のラベルが変わった・当時の ROI と基準画像が見つからない画角・イベントの重複・保護していない録画を表示します。`freeze` はこれらの問題（保護を除く）がなければ、除外した録画を落として `evaluation-v1.json` に版1として書き、内容の SHA-256 を付けます。固定した録画は自動整理から保護します。既存のファイルは上書きしません。固定した版を書き換えると読み込みを断るので、直すときは下書きを直して次の版で固定します。

### 4. 比較する

```bash
uv run poop-detector video-benchmark \
  --dataset data/benchmarks/datasets/evaluation-v1.json \
  --judge codex:利用するモデル名 \
  --judge claude:利用するモデル名 \
  --judge gemini:利用するモデル名 \
  --send-images
```

比較の前に、評価セットの録画・ラベル・画角の登録情報を確かめ、問題があれば判定器を動かさずに止めます。録画ごとに撮影時の ROI と基準画像で画像を一度だけ切り出し、同じ画像と判定指示を選んだすべての判定器に渡します。`--track-tray` を付けるときは、各画角の `baseline/tray-reference.png` を使います。下書きのままでは比較しません。

`--send-images` を指定すると、同じ抽出画像と判定指示を選んだ提供元に送ります。認証方法は[判定器とモデルを選ぶ](video.md#判定器とモデルを選ぶ)を参照してください。テストの通知は送信せず、運用中の判定・確定記録・正解ラベルは更新しません。

手書きの評価セットも、これまでどおり使えます。

```json
{
  "clips": [
    {"id": "録画のID", "event": "排泄や滞在を区別する名前", "tags": ["夜間", "メッシュ付き"]},
    {"id": "別の録画のID", "tags": ["通過"]}
  ]
}
```

手書きの評価セットでは、1回の評価に同じ検知範囲と基準で撮影した録画を選びます。過去の基準で撮った録画は `--scene` に当時の ROI と基準画像の保存先を指定します。録画 ID は動画詳細ページの URL の `id` にあります。

### 5. 結果を見る

結果は `data/benchmarks/` に作成時刻の名前の JSON で保存し、GUI の「管理 › 判定器とモデル」に新しいものから5件を出します。新しい結果は、録画ごとに正解と各判定器の回答を並べ、正解と違う回答に印を付けます。評価セットの件数と欠損も同じ画面に出ます。別の場所に保存するときは `--output 新しいファイル` を付けます（画面には出ません）。既存のファイルは上書きしません。

端末に排便・排尿ごとの適合率と再現率が表示されます。JSON には次を残します。

- 評価セットのファイル名と SHA-256、名前・版・内容の SHA-256（`dataset_info`）
- 判定器ごとの指定したモデルと CLI の版（`judges`。読めなければ `null`）
- 録画ごとの正解・分割・条件・画角の署名、抽出した画像と判定指示の SHA-256、画像の時刻、抽出した時刻、各判定器の回答（`cases`）
- 判定器ごとの全体・条件別（`by_tag`）・分割別（`by_split`）の集計。「両方」「排泄なし」を含む取り違え、判定不能とエラーの件数

「両方」は排便と排尿の双方に含まれます。再現率の分母は判定不能やエラーになった動画も含む全正解陽性です。適合率の分母はその種類を検出したと判定した件数です。分母が0の指標は JSON で `null` になります。

評価セット・結果・録画・切り出し画像はローカルに置き、GitHub などに添付しないでください。
