# データの保存先と外部への送信

このツールは室内のカメラ映像を扱います。ここでは、どのデータがどこに保存され、どの機能を使うと何が外部に送られるかをまとめます。脆弱性の報告方法は [SECURITY.md](../SECURITY.md) を参照してください。

## まとめ

- 映像はすべて手元のマシンで処理します。外部に映像が送られるのは、動画の自動判定（`--video-review`、`video-review`）を使ったときだけです。
- 利用状況の収集（テレメトリー）は行いません。
- 外部に送信する機能は、どれも明示的に設定するか、コマンドやオプションを指定したときだけ動きます。

## 手元に保存するデータ

既定ではリポジトリ直下の `data/`（設定の `data_dir`）に保存します。`data/`、`.env`、`config/config.yaml` は Git の管理対象外で、Docker イメージにも含めません。

| 保存先 | 内容 |
|---|---|
| `data/roi.json`、`data/outside-roi.json` | 監視範囲の座標 |
| `data/baseline/` | 空のトイレの基準画像、トレー追従用の画像 |
| `data/events/` | 検知したときの画像 |
| `data/clips/` | 検知前後などの動画（MP4） |
| `data/events.sqlite3` | 検知の記録、ラベル、排泄の記録、動画の情報、動画の自動判定の結果、GUI のセッション（ID の SHA-256 と時刻だけ） |
| `data/activity.sqlite3`、`data/activity-*.jpg` | 行動マップの集計と、登録時の床面の画像 |
| `data/models/` | 犬検出モデル |
| `data/.live-preview.jpg` | GUI に表示する最新の映像（GUI を開いている間だけ更新） |
| `.env` | カメラの RTSP URL（認証情報を含む）、ntfy のトピック名とサーバー |

古い動画は GUI の「録画容量と古い動画の整理」で削除できます（動画ファイルだけを消し、記録は残ります）。すべてのデータを消すには、監視と GUI を止めてから `data/` ディレクトリを削除してください。

## 外部への通信

| 機能 | 既定 | 送信先 | 送るもの |
|---|---|---|---|
| カメラの映像の取得 | 常に | 設定したカメラ（RTSP） | なし（映像を受け取るだけ） |
| ntfy の通知 | `POOP_NTFY_TOPIC` を設定したときだけ | `ntfy.sh`、または `POOP_NTFY_SERVER` のサーバー | トピック名、通知のタイトルと短い本文（犬の名前を含むことがあります）。映像やカメラの URL は送りません |
| macOS の通知 | ntfy を設定していない macOS | なし（手元の通知センター） | なし |
| 動画の自動判定 | `run --video-review` または `video-review` を実行したときだけ | 選択した判定器の提供元（OpenAI、Anthropic、Google） | 動画から切り出した最大24枚の画像を並べた1枚の画像（トレー追従時は差分を強調した画像も）と、判定を依頼する文 |
| 犬検出モデルの取得 | `setup-dog-model` を実行したときだけ | GitHub（OpenCV Zoo の固定版） | なし（モデルを受け取り、SHA256 を検証します） |
| GUI | `gui` または `run --gui` を実行したとき | なし（`127.0.0.1` で待ち受け） | なし |

### ntfy

無料の `ntfy.sh` のトピックは公開扱いで、トピック名を知っている人なら誰でも通知を読めます。`openssl rand -hex 16` などで推測しにくい名前を作り、家族内だけで共有してください。`POOP_NTFY_SERVER` に `http://` を使うと、通知の本文が暗号化されずに流れます。信頼できる LAN 内のサーバーに限ってください。

### 動画の自動判定（Codex CLI）

動画の自動判定では Codex CLI、Claude API、Gemini API を選べます。Claude API と Gemini API には、選んだ提供元の API キーを使い、切り出した画像と判定指示を送ります。各提供元のデータの取り扱いと利用条件を確認してください。

Codex CLI には、利用者自身のアカウントでログインしたものを使います。送った画像の扱いは、Codex CLI の提供元の規約に従います。このツールは Codex CLI を次の制限付きで起動します。

- サンドボックスを読み取り専用にし、シェルの実行を無効にする
- 利用者の Codex の設定とルールを読み込まず、会話を保存しない
- 一時ディレクトリで実行し、環境変数は `HOME`、`PATH`、`CODEX_HOME`、`TMPDIR`、`LANG`、`LC_ALL` だけを渡す（`.env` の RTSP URL などは渡しません）

## GUI の安全対策と限界

GUI は既定で `127.0.0.1` だけで待ち受け、同じマシンからしか接続できません（外から開く場合は [外から GUI を開く](remote-access.md)）。そのうえで次の対策をしています。

- 起動ごとにアクセス用のトークンを作り、トークン付きの URL を開いたブラウザーだけが閲覧できるようにする。トークン付きの URL を開くとサーバー側のセッションを始め、そのランダムな ID を HttpOnly・SameSite=Strict の Cookie に入れ、URL からトークンを取り除く。以後は画面、画像、動画、ライブ映像、スクリプトを含むすべての要求でセッションを確かめ、有効でない要求には 403 を返す
- データベースには、セッションの ID そのものではなく SHA-256 だけを保存する。セッションは、操作がないまま `gui.session_idle_hours`（既定168時間）が過ぎるか、始めてから `gui.session_max_days`（既定30日）が過ぎると切れる。画面右上の「ログアウト」で、その場で終えられる
- 起動トークン付きの URL・フォームの送信・すべての要求の回数を接続元ごとに制限し、総当たりと連打を防ぐ（上限を超えると 429 を返す）
- トークン付きの URL は端末に直接表示するときだけ出力し、出力をファイルに送っている場合は表示しない
- `Host` ヘッダーを確かめ、DNS リバインディングによる外部サイトからの読み出しを防ぐ
- 保存などの操作には、セッションごとに異なる CSRF トークンを必須にし、CSRF を防ぐ（セッションの ID と起動ごとの鍵の HMAC で、別のセッションの画面から取ったトークンは使えない）
- Content Security Policy でインラインスクリプトと外部への読み込みを禁止し、ほかのサイトに埋め込まれないようにする。`Referrer-Policy: same-origin` で URL をほかのサイトへ渡さない
- 動画の配信は `data/clips/` の中のファイルに限る

起動トークンは GUI を再起動するたびに変わり、前回の URL は使えなくなります。一方、始めたセッションは再起動しても有効期限まで続くので、使い終えた端末や共有の端末では「ログアウト」してください。次の点は防げません。

- 起動した OS ユーザー自身の権限で動くプログラムは、端末の表示やブラウザーの Cookie からトークンを読めます
- Linux などでブラウザーを自動で開くと、トークン付きの URL が一瞬だけコマンドライン引数としてプロセス一覧に現れ、他の OS ユーザーに見える場合があります。共有のマシンでは `--no-browser` で起動し、端末に表示された URL を自分でブラウザーに貼り付けてください（macOS の自動起動は引数に URL を載せません）
- Cookie はポート番号を区別しないため、同じマシンで `127.0.0.1` の別のポートに置かれた悪意のあるページを開くと、Cookie がそのページへ送られます。GUI を使い終えたらログアウトし、Ctrl+C で止めてください

ポート転送などで外部に公開しないでください。

## 認証情報の扱い

- RTSP URL は `.env` にだけ書き、Git にコミットしないでください。ルーターの RTSP ポートを外部に公開しないでください。
- FFmpeg の診断メッセージには URL が含まれることがあるため、OpenCV を読み込む前に FFmpeg のログを止めています。
- 外部ライブラリの例外メッセージは表示せず、固定の文言だけを出します。そのため、エラーの原因が分かりにくいことがあります。
- `POOP_NTFY_SERVER` に認証情報を含む URL は指定できません。
