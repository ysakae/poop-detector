# 判定の仕組み

## 差分による検知

OpenCV でグレースケール、ぼかし、差分、二値化、モルフォロジー、輪郭面積・縦横比の処理を行います。
ROI 面積の18%以上が変わると犬などの遮蔽とみなし、広範囲の明るさの変化も保留します。
面積が18%未満でも、最小輪郭面積以上の差分が ROI の端に接していれば遮蔽として保留します。
端の余白は ROI の短辺の1%（最低1ピクセル）です。端から入り込む足・体の一部による誤通知を抑えます。
この間は内側の候補も通知せず、遮蔽がなくなってから継続確認をやり直します。
端に接した排泄物も保留されるため、ROI の端がトイレの検知したい範囲を切らないように設定してください。
小さな変化が既定3秒続くと SUSPECTED として1回通知します。score は差分画素率で、排便の確率ではありません。

## 状態と再通知の抑制

状態は EMPTY / OCCUPIED / VERIFYING / SUSPECTED / ACKNOWLEDGED です。
画像差分から CONFIRMED にはしません。切断や遮蔽では継続確認のタイマーをリセットします。
通知した跡は「通知済み状態」として保存し、同じ跡の再通知を抑制します。
その状態との差分から、空の基準画像とも異なり、基準へ戻る方向ではない追加の変化を検知します。
追加の跡・広がり・濃さの増加を継続確認すると、シートを交換しなくても別イベントとして通知します。
フレーム間に大きな動きがあれば継続確認をやり直します。便・尿を直接認識する方式ではありません。
清掃や乾燥で基準へ戻る変化は追加排泄から除外し、安定した状態が3秒続くと通知済み状態を更新します。
空の基準画像のファイルは自動更新しません。通知済み状態は SQLite 内の別テーブルへ PNG で保存します。
イベントと通知済み状態を同じトランザクションで保存し、再起動時にも復元します。
ROI または空の基準画像が変わった場合は旧状態を流用しません。確認済み操作だけで再通知することもありません。

## 排尿の検知

明るさの差分に加え、Lab 色空間の色差を候補に使います。色差閾値は `color_threshold`（既定20、0で無効）です。
濡れ跡など、映像上で見える変化が対象です。吸収されて見えない尿、薄い濡れ跡、犬に隠れた状態は検知できないことがあります。
色のある物体や照明変化でも候補になるため、尿と確定する機能ではありません。実排尿映像での精度・遅延は未測定です。
小さい色変化を拾うようになった分、実映像で誤検知・見逃しをラベル付けして調整する必要があります。

尿跡や便が残っていても、通知済みの状態からの追加変化を監視します。交換は検知再開の必須条件ではありません。
同じ位置への排泄でも跡の広がりや十分な濃さ・色差があれば候補になりますが、
既存の跡とほぼ同じ見え方の排泄や、画像上の変化がない排泄は検知できません。
乾燥・影・シートのずれ等を完全に区別する仕組みではなく、実映像での追加検知精度は未検証です。
見逃しは手動記録で補ってください。
この追加検知方式を初めて起動する際、旧版に通知済み状態が保存されていない場合は既存の跡を初回候補として扱うことがあります。

## 録画を待たずトイレの様子を知らせる

排泄の前後に様子を見に行きたい場合は、監視コマンドに `--early-alert` を追加します。

```bash
uv run poop-detector run --dog --video-review --early-alert
```

トイレ内で動きを確認し、その後、約4秒にわたり同じ位置にとどまった場合に「トイレで同じ場所にとどまっています」と通知します。起動・再接続時から静止したままの場合や、小さな動きだけの場合は通知を開始しません。
変化の位置を手元のマシンで追い、録画の完了や動画の自動判定を待たずに通知します。
同じ滞在では一度だけ通知し、別の滞在でも30秒以内の再通知を抑えます。滞在の長さ（既定4秒）と再通知までの間隔（既定30秒）は、`config/config.yaml` の `early_alert.stay_seconds` と `early_alert.cooldown_seconds` で変えられます。
動画保存が有効ならこの時点でも前後の動画を保存し、動画 GUI に「トイレ見守り」と表示します。
動いた直後に寝そべった場合や、食事・座り込みでも反応することがあります。通知が来たら映像やトイレを確認し、排便していた場合は終わってからトイレの外へ誘導できます。

ntfy を使う場合は、見守り通知だけを別のトピックに送れます。[通知](notifications.md) を参照してください。

## 映像の取得と処理の頻度

取得専用スレッドが映像を継続して読み、最新の未処理フレーム1枚だけを保持します。
設定の `fps` は**検出処理の FPS**です。RTSP 受信・デコード自体はカメラの配信 FPS で行い、映像の滞留を防ぎます。
接続・読込タイムアウトは既定5秒、再接続待機は2秒です。30秒ごとに CPU、RSS メモリー、処理時間をログ出力します。

## 設定項目

`config/config.yaml` で fps、継続秒数、閾値、面積、遮蔽率、通知の有効・無効、保存先を変更できます。
`min_area` は ROI 内のピクセル面積なので、解像度と設置位置に応じて調整してください。
項目と既定値は `config/config.example.yaml` を参照してください。

## 処理負荷の参考値

640×480 の人工画像では、初期 MVP の差分検知の実測値を [validation.json](validation.json) に記録しています。
追加検知版では640×480の人工画像100回で、追加検知と前フレームとの動き確認を合わせて平均約31ms/フレームでした。
どちらも RTSP の受信・デコード負荷を含みません。測定条件は [docs/README.md](README.md) を参照してください。

## 制限

- ROI 内の小さな犬・影・シートのずれ、動かない犬、照明変化で誤検知・見逃しが起こりえます。
- 犬の全身が ROI 内に収まり、差分面積も遮蔽率未満の場合は、端の遮蔽対策では除外できません。犬の検出（`--dog`）を併用すると、検出枠が ROI に重なる間は判定を保留します。
- 犬がトイレを離れて変化が安定するまで通知できず、食糞までに間に合う保証はありません。
- 既定3秒の確認時間に、最大1フレーム間隔・通信・通知処理の遅延が加わります。
- 実際の排泄の映像がないため、実際の Precision・Recall・通知遅延は未測定です。
