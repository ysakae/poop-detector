# 鳴き声らしさを分類するモデルの調査（#295）

鳴き声の記録（[鳴き声の記録](vocal.md)、#288）は、音量と鳴き声の帯域（300〜4000Hz）の割合だけで判断するので、テレビ・人の声・インターホンも数えることがあります。手元で動く小さな音声分類モデルで、鳴き声らしさを確かめられるかを調べました。

この文書は調査の結果と、評価の進め方の提案です。モデルの取得と、実際の音での比較は、まだしていません（下の「次にすること」）。

## 結論

- 第一の候補は **YAMNet**（Google、AudioSet の521クラス）です。「Dog」「Bark」「Whimper (dog)」などのクラスを持ち、ライセンスは Apache 2.0、重みは数MB〜16MB と軽く、CPU で十分に動きます。
- 使い方は、いまの音量と帯域の判断を「候補を見つける段」としてそのまま使い、候補の窓（鳴いていた区間）だけに YAMNet をかけて「鳴き声らしいか」を確かめる二段構えにします。常時かけないので、CPU の使用量はほとんど増えません。
- 依存は任意（`pip install poop-detector[audio-model]` のような extras）にし、モデルがなければ今の判断だけで動くようにします。犬検出（YOLOX）のように、データの保存先の `models/` に取得する形が合います。
- 採用するかは、人がラベルを付けた評価セットで、いまの帯域の割合と比べてから決めます。会話を録らない方針（#288）を崩さないよう、評価セットの作り方を先に決める必要があります。

## 候補

| モデル | クラス | ライセンス | 大きさ | CPU での重さ | 備考 |
|---|---|---|---|---|---|
| いまの判断（音量＋帯域の割合） | なし（鳴き声らしさの近似） | — | — | ほぼなし | 生活音と区別できないことがある |
| YAMNet | AudioSet 521クラス（Dog・Bark・Whimper (dog)・Howl など） | Apache 2.0 | TFLite 約16MB、量子化 約4MB、ONNX（float16）約7.5MB | 軽い（MobileNet v1 系） | 0.96秒の窓ごとに判定。16kHz・モノラル |
| PANNs CNN14 | AudioSet 527クラス | コードは MIT 系、重みは CC-BY-4.0 | 約81M パラメーター、fp16 で約162MB | 重い（10秒あたり 50G MACs 超） | 精度は高いが、常時の監視の横で動かすには重い |
| 小さな PANNs・EfficientAT の系統 | AudioSet | 系統ごとに確認が要る | CNN14 より小さい | 中くらい | YAMNet で足りなければ次に試す |

YAMNet の「Dog」「Bark」「Whimper (dog)」は AudioSet のクラスのまま使えます。AudioSet から外された6クラスに、犬に関わるものはありません。

## YAMNet の組み込み方（案）

- **実行**：TensorFlow を入れずに、ONNX に変換済みのモデルを `onnxruntime` で動かします。生の波形（16kHz・モノラル・float32）を受け取る変換と、log-mel の特徴量を自分で作る変換があるので、波形を受け取るものを選ぶと実装が小さくなります。OpenCV の DNN（犬検出で使っている `cv2.dnn`）で読めるかは、演算の対応しだいなので、まず `onnxruntime` で試します。
- **入力**：いまの `experimental/vocal.py` は 16kHz・モノラルの PCM を0.5秒ごとに受け取っているので、候補の区間の音（1〜数秒）をメモリーの上だけで保ち、区間が閉じたときに YAMNet に渡します。音声はディスクに書きません。
- **判断**：犬に関わるクラス（Dog・Bark・Yip・Howl・Bow-wow・Growling・Whimper (dog)）の確からしさの最大値が、しきい値を超えた区間だけを記録します。人の声（Speech）・テレビ（Television）・音楽（Music）などのクラスが高い区間は、鳴き声から外す候補にします。
- **記録**：区間ごとに、犬に関わるクラスの確からしさの最大値だけを `vocal_episodes` に足します（音声も埋め込みも残さない）。

## 評価の進め方（案）

音声を保存しない方針と、評価に音が要ることがぶつかるので、次のどちらかを家族で決めてから進めます。

1. **確からしさだけを残して、人が映像で確かめる**：音声は残さず、区間ごとに「いまの判断」と「YAMNet の確からしさ」を記録し、同じ時刻の動画やライブ映像で人が「鳴いていた／ほかの音」を付けます。映像で鳴いているかは分かりにくいので、ラベルの質は下がります。
2. **同意したうえで、短い音を期間を決めて残す**：評価の間だけ、候補の区間の音（数秒）を保存し、人が聞いてラベルを付けたら消します。保存期間（例: 7日）と、家族全員の同意を先に決めます。バックアップには入れません。

どちらでも、日ごとに分けた評価（#127 と同じく、日をまたいで学習と評価を分ける）で、次を比べます。

- 鳴き声の区間を見つけられた割合（見逃しの少なさ）
- 鳴き声と数えた区間のうち、本当に鳴き声だった割合（テレビ・人の声などを数えない度合い）
- CPU の使用量（監視と同じマシンで、候補の区間だけにかけたとき）
