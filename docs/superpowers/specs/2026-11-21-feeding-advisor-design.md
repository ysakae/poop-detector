# ごはんの量の目安と相談（設計）

## 意図

子犬の成長に合わせて、ごはんの量を調整したい。月齢と体重の伸びに合わせて1日の量を見直す必要があるが、いまの GUI は体重と給餌の記録を残すだけで、「今日は何 g あげればよいか」は分からない。

この先は、成犬の健康体重の維持やフードの切り替えも相談したい。家族全員がこの機能を使い、相談の履歴は家族で共有して残す。

## 目標

- 月齢・最新の体重・犬種（成犬時の体格）・去勢・避妊の有無・フードのカロリーから、1日の量の目安（kcal と g）を計算して示す。給餌の予定があれば、1回分の量も示す。
- 目安の横に、体重の推移と、実際に与えた量（直近7日の給餌記録）を並べる。
- 目安の数字と記録を前提に、AI に自由に相談できる。相談は話題ごとの会話に分け、家族全員が読み書きできる。履歴は残す。
- フードを登録するときは、名前から AI がメーカーのページを探し、kcal/100g と出典の URL を下書きする。人が確かめてから保存する。

## 目標にしないこと

- 量の数字を AI に決めさせること。数字は計算で決め、AI は説明と助言だけを受け持つ。
- 回答を少しずつ流して表示すること。回答は届いたときにまとめて出す。
- 給餌の予定や記録を、AI の回答から自動で書き換えること。
- フードの切り替えの日程表や、減量用のカロリー計画を計算すること。最初の版では、AI との相談で扱う。
- 複数の犬。いまのプロフィール（`pet_profile`）と同じく、1頭だけを扱う。
- 病気の診断。

## 失敗とみなすこと（動いていても）

- AI が作ったカロリーの値を、人が確かめないまま計算に使うこと。
- 古い体重で子犬の量を計算し、それに気付けないこと（与えすぎ・不足につながる）。
- 相談が動画の自動判定の呼び出し回数を食い、判定が止まること。
- 家族のうち誰かが画面を閉じたり、送信を押し直したりしたせいで、回答が消える・二重になること。

## 前提と制約

- 生年月日（`pet_profile.birth`）、体重（`weights`）、給餌の記録（`care_entries` の `food`・`amount_dg`）、給餌の予定（`feeding_plans`）はすでにある。給餌の記録のフードは名前の文字列だけで、カロリーは持っていない。
- AI は、動画の自動判定と同じ CLI（Codex CLI・Claude Code CLI・Antigravity CLI。`video/providers.py`、`video/codex_cli.py`）を使う。新しい API キーや契約は増やさない。
- CLI の応答には数十秒かかることがある。GUI のルートは同期の関数なので、要求の中で回答を待たない。
- スキーマの変更は `records/database.py` の `MIGRATIONS` の末尾に足す（いまは版30まで）。既存の移行処理は書き換えない。
- HTML は Jinja2 のテンプレートで作る。JavaScript は `gui/static/` に置く（CSP でインラインスクリプトは動かない）。
- AGENTS.md のテスト・Lint・型の規約に従う。CLI は偽物に差し替えてテストし、実際の CLI には依存させない。

## 作り方の案

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A（採用）** | 既存の CLI を使う。質問を台帳に入れ、GUI の中の作業スレッドが回答を作る。画面は回答が届くまで待ちの表示を出す | 新しいキーや課金がない。画面を閉じても回答は残る。家族で共有しやすい | 回答を少しずつ流して表示できない |
| B | 既存の CLI を使い、送信した要求の中で回答を待つ | 作りが最も簡単 | 1〜2分待つと、外出先の回線やプロキシで切れやすい。押し直すと二重に送られる |
| C | Anthropic の API を直接呼ぶ | 回答を少しずつ流せる | API キーと従量課金が増える。サブスクリプションの CLI で動かすいまの方針から外れる |

利用者は A を選んだ。量の数字は計算で決め、AI はその数字と記録を前提に相談に答える（「計算」と「AI との会話」の両方を使う案。これも利用者が選んだ）。

## 設計

### 1. プロフィールの追加（版31）

`pet_profile` に次の列を足す。

- `breed TEXT`：犬種の名前（自由入力。候補は下の表から出す）
- `size_class TEXT`：成犬時の体格。`toy`・`small`・`medium`・`large`・`giant` のどれか
- `adult_grams INTEGER`：成犬時の予想体重（g）
- `neutered INTEGER`：去勢・避妊の有無（1・0・NULL＝未入力）
- `food_id TEXT`：いま主に食べているフード（`foods.id`）

犬種を選ぶと、体格と予想体重を表から下書きする。人が直せる。表は `records/breeds.py` に定数として持ち、日本でよく飼われる犬種を20前後並べる（トイ・プードル、チワワ、ミニチュア・ダックスフンド、ポメラニアン、柴、フレンチ・ブルドッグ、ゴールデン・レトリーバーなど）。表にない犬種や雑種は、体格と予想体重を手で入れる。

プロフィールの入力欄は、相談の画面の「プロフィール」の欄にまとめる。生年月日は体重の画面にもあるが、保存先は同じ列。

### 2. フードの台帳（版31）

- `foods`：`id`、`name`（一意）、`kcal_per_100g_dk`（0.1 kcal 単位の整数）、`source_url`（https のみ・任意）、`created_by`（`users.id`）、`created_at`、`active`
- `food_lookups`：カロリーを探す依頼。`id`、`name`、`status`（`queued`・`running`・`done`・`failed`）、`product_name`、`maker`、`kcal_per_100g_dk`、`source_url`、`note`、`failure`、`requested_by`、`requested_at`、`finished_at`

手順：

1. フードの画面（`/advice/foods`）で名前を入れて「カロリーを探す」を押すと、`food_lookups` に `queued` の行が入る。給餌の記録にあって未登録のフード名は、候補として並べる。
2. 作業スレッドが、ウェブ検索を許した CLI に「メーカーの公式ページを優先して、代謝エネルギー（kcal/100g）と出典 URL を返す」ように頼み、JSON スキーマで受け取る。
3. 画面は、見つけた商品名・メーカー・kcal/100g・出典の URL（文字とリンクの両方）を下書きとして出す。人が値を直し、「この値で登録」を押したときだけ `foods` に入る。
4. 探せなかったとき、ウェブ検索に対応しない判定器のときは、手で入れる欄だけを出す。

値の範囲は 30〜700 kcal/100g（ウェットとドライの両方を許す）。出典の URL はサーバーから開かず、表示するだけにする（`rel="noopener noreferrer"`）。

### 3. 目安の計算（`records/feeding_advice.py`、副作用のない関数）

体重 kg を BW とする。

- 安静時のエネルギー量 RER = 70 × BW^0.75
- 成長期（月齢が体格の成犬月齢より前）は、成犬時の予想体重に対する割合 p = BW ÷ 予想体重で係数を変える：p < 0.5 は3.0、0.5 ≦ p < 0.8 は2.5、0.8 ≦ p は2.0。ME = RER × 係数。成犬月齢は、toy・small が10か月、medium が12か月、large が15か月、giant が18か月。
  - NRC（2006）の成長期の式（130 × BW^0.75 × 3.2 × (e^(−0.87p) − 0.1)）も検討したが、小型犬の子犬で RER の約2.8倍と多めに出るので採らない（3.2 kg・予想 5 kg の例）。
  - 予想体重が未入力で犬種の表からも決まらないときは、月齢で決める：4か月未満は3.0、それ以降は2.0。この場合は「成犬時の予想体重を入れると目安が正確になります」と警告する。
- 成犬は、維持の係数を RER に掛ける。去勢・避妊済みは1.6、未実施は1.8、未入力は1.6。
- 1日の g = ME ÷ (kcal/100g ÷ 100)。給餌の予定が1件以上あれば、その件数で割った1回分も出す。0.1 g 単位まで計算し、画面では 1 g 単位に丸める。
- 返す値：月齢、使った体重とその測定日、成犬時の予想体重に対する割合、式の名前と途中の値（RER・係数か p）、kcal/日、g/日、1回分、警告の一覧。

警告（計算は止めず、目安の上に出す）：

- 体重が古い：成長期で14日、成犬で60日を超えた測定しかない。
- 生年月日か体重がない（目安は出さず、何を入れればよいかを示す）。
- 体格が決まらない（設計者の判断）：体格は、犬種の表、手入力、予想体重からの推定の順に決める。推定のしきい値は、4 kg 未満を toy、10 kg 未満を small、25 kg 未満を medium、45 kg 未満を large、それ以上を giant とする。予想体重もないときは、成犬月齢を12か月として計算し、「犬種か成犬時の予想体重を入れると目安が正確になります」と警告する。
- フードのカロリーがない（kcal/日だけを出す）。
- 月齢が2か月未満（式の対象外。獣医師に相談するよう示す）。

画面には、目安であることと「獣医師の指示があればそちらを優先してください」を常に出す。

あわせて示す実績：

- 体重の伸び：直近28日の測定から求めた g/週（2件以上あるとき）。標準の範囲との比較は計算では出さず、AI に解釈を任せる。
- 直近7日の給餌：日ごとの g の合計と平均。フード名が台帳と一致する日は kcal も出す。

### 4. 相談の会話（版31）

- `advice_threads`：`id`、`title`、`created_by`、`created_at`、`updated_at`、`deleted_at`
- `advice_messages`：`id`、`thread_id`、`role`（`user`・`assistant`）、`author`（`users.id`。AI の行は NULL）、`body`、`status`（`queued`・`running`・`done`・`failed`）、`failure`、`basis`（質問を送った時点の目安の要約。JSON の短い文字列）、`provider`、`model`、`created_at`、`answered_at`

流れ：

1. 相談の画面（`/advice`）で題名と最初の質問を入れて送信すると、会話と質問の行、`queued` の回答の行が入る。2回目以降は会話の画面（`/advice/thread?id=…`）から送る。
2. 回答が `queued`・`running` の会話では、次の質問を受け付けない（二重送信と順番の入れ替わりを防ぐ）。
3. 作業スレッドが、次の内容を指示文にまとめて CLI に渡す。ツールは使わせない（いまの判定と同じ、ウェブ検索なし）。
   - 犬のプロフィール（名前・月齢・犬種・体格・成犬時の予想体重・去勢・避妊）
   - 計算した目安と式の途中の値、警告
   - 直近90日の体重（多ければ間引いて30点まで）
   - 直近14日の給餌（日ごとの g・kcal・フード名）と、給餌の予定の回数
   - 直近14日の排便・排尿の確定記録の回数（日ごと）
   - 登録済みのフードと kcal/100g
   - この会話の直近20件のやりとり（合わせて2万文字まで、古い方から削る）
   - 指示：日本語で答える。量の数字は上の目安を基準にし、変えるよう勧めるときは理由と幅を示す。嘔吐・下痢が続く、元気がない、体重が減るなどのときは受診を勧める。
4. 回答は JSON スキーマ（`{"answer": string}`）で受け取り、`done` にする。画面では、改行だけを保ったプレーンテキストとして、自動エスケープして出す。
5. 失敗したら `failed` と失敗の種類（`judge_failures` の分類）を残し、画面に「もう一度聞く」を出す。押すと同じ行を `queued` に戻す。

待ちの表示：`gui/static/advice.js` が、回答が届くまで数秒おきに JSON の窓口（`/advice/status?thread=…`）を確かめ、届いたら画面を読み直す。スクリプトが動かなくても、「読み直す」のリンクで確かめられる。

権限：ログインした人なら誰でも、会話の閲覧・作成・送信ができる。会話の削除（`deleted_at` を付けるだけ）は、作った人か管理者だけができる。フードの登録と訂正は誰でもできる。

### 5. 作業スレッド（`gui/advice_worker.py`）

`feeding_notifications.feeding_reminders` と同じく、GUI のサーバーの起動中に動く1本のスレッド（コンテキストマネージャー）にする。`gui` と `run --gui` のどちらでも動く。

- 2秒ごとに、`queued` の回答とカロリー探しを古い順に1件ずつ取り、`running` にしてから CLI を呼ぶ。行の取り出しは `BEGIN IMMEDIATE` で行い、2つの GUI が同じデータを見ていても二重に処理しない。
- 起動したとき、`running` のまま `answered_at` がない行で、CLI の時間切れ（いまの判定と同じ上限）を過ぎたものは `failed` にする。
- 判定器は `review.provider`・`review.model` の設定から作る。予備の判定器（`review.fallback`）は使わない。
- 動画の自動判定（`video_review_enabled`）が無効でも動かす（設計者の判断）。相談はカメラや動画と関係なく使いたいため。判定器が使える状態か（`judge_readiness`）を画面を開くときに確かめ、使えないときは目安とフードの手入力だけを出し、相談の欄の代わりに理由（例：「codex login で Codex CLI にログインしてください」）を示す。
- 相談は、動画の判定の待ちがあっても後回しにしない（利用者の判断）。家族が画面で回答を待っているため。CLI のサブスクリプションの利用枠は判定と共有するので、相談が判定を遅らせることはありうる。その影響は、上の1時間20回の上限で抑える。
- `JudgeRunLog.count_since` は、いまは用途を区別せずに数える。動画の判定の上限（`Review._waiting`、`review_status`）が相談の回数を数えないよう、用途で絞れるようにし、判定の側は `review`・`benchmark` だけを数える。
- 呼ぶたびに `judge_runs` に記録する。`PURPOSES` に `advice` と `food_lookup` を足し、管理 › 判定器とモデルの使用量にも出す。
- 呼び出しの上限は、動画の判定の `review.max_per_hour` とは別にする。相談とカロリー探しを合わせて1時間に20回（定数）までとし、超えた分は `queued` のまま待たせる。画面には「混み合っているので順番を待っています」と出す。

### 6. CLI への口

いまの判定器の `judge(folder, prompt, images, schema)` は、画像なしでも呼べる。相談の回答はこの口をそのまま使う。

カロリー探しにはウェブ検索が必要なので、判定器に新しい口を足す（例：`lookup(folder, prompt, schema)`。Codex CLI はウェブ検索を有効にし、Claude Code CLI は `--tools` で WebSearch と WebFetch だけを許す）。ウェブ検索以外のツール（シェル・ファイルの書き込み）は許さない。対応しない判定器は、口を持たないことで「手入力だけ」に倒す。

### 7. 画面

メインメニューに「ごはんの相談」（`/advice`）を足す。

```
ごはんの目安 ─ 5か月・3.2 kg（11/18 測定・小型・成犬 約5 kg予想）
  1日 109 g（1回 36 g × 3回）  フード：○○パピー 385 kcal/100g
  直近7日の実績：平均 98 g/日
  体重の伸び：+120 g/週
  ※目安です。獣医師の指示があればそちらを優先してください。
────────────
相談
  ・子犬の量（11/20 更新・ゆう）
  ・フードの切り替え（11/12 更新・あや）
  [ 題名 ] [ 質問 ] [送信]
────────────
プロフィール（犬種・体格・成犬時の予想体重・去勢・避妊・いまのフード）
フード（登録済みの一覧・カロリーを探す）
```

ホームには、目安があるときだけ「今日の目安 109 g」を1行で出す（給餌量の表示の近く）。

## 作る人に任せること

- 犬種の表の中身（犬種名・体格・成犬時の予想体重）。一般的な資料の中央値でよい。
- Codex CLI と Claude Code CLI で、ウェブ検索だけを許す正確な引数。いまの CLI の版で確かめること。Antigravity CLI が対応するかも確かめること。
- 指示文の言い回しと、JSON スキーマの細部。
- 画面の細部の配置とスタイル（いまの `style.css` の変数に合わせる）。

- `docs/architecture.md`、`docs/screens.md`、README の機能表の更新。

## テスト

- 計算：月齢・体格・去勢の組み合わせごとに、手で計算した値と一致するか。警告の出る条件の境目。
- 移行：版30のデータベースから版31へ移したとき、既存のプロフィール・体重・記録が残ること（`tests/test_database.py`）。
- 作業スレッド：偽の判定器で、`queued`→`running`→`done`・`failed` の遷移、二重に取り出さないこと、起動時の取り残しの整理、1時間の上限、`judge_runs` の記録。
- 画面：フードの登録（下書き→確定、手入力）、会話の作成と送信、回答待ちの間は次の送信を断ること、削除の権限、特殊文字のエスケープ（`tests/test_gui_escaping.py`）、ルートの役割（`tests/test_gui_roles.py`）。
