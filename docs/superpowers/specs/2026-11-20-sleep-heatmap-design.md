# 睡眠時間の記録と見える化 設計

## 目的と背景

監視カメラの映像から犬が寝ていた時間を割り出し、GitHub のコントリビューショングラフのような「マス目 × 色の濃さ」で見えるようにする。所有者が知りたいことは次の3つ。

1. 1日あたりの睡眠時間。十分に寝ているか。
2. 日中（留守の間）にどの程度寝ていたか。帰宅後にどのくらい遊ぶ必要があるかの目安。
3. いつもと違う寝方から、体調の変化に気付くこと。

## 前提（所有者から確認済み）

- 寝床は決まっていない。トイレトレーの上で寝ることもよくある。範囲（`bed_zone` など）で睡眠を決めない。
- 犬を部屋に放していてカメラに映らない時間がある。サークルの外にいるときは基本的に起きている。したがって「映っていない＝起きている」として数える。
- 保存済みの動画はきっかけがあるときだけの飛び飛びの録画なので、睡眠の判定には使えない。監視中の映像から記録する。

## 目標・非目標・失敗とみなすこと

- 目標: 毎日欠けずに、1分単位の睡眠の状態を記録し続ける。日付 × 時刻の草の画面、1日の合計、日中の合計、いつもとの差を GUI で見られる。
- 非目標: 過去（実装前）の分の睡眠の推定。睡眠の質（レム・ノンレム）の推定。保存済み動画の再解析。睡眠に関する通知（まずは見える化だけ）。
- 失敗とみなすこと: 監視の停止やカメラの不調の時間を「起きていた」と数えて、睡眠不足に見せてしまうこと。排泄やトレーでの短い静止を睡眠として大きく数えること。室内の映像を新たに常時保存すること。

## 検討した方法

| 案 | 内容 | 採否 |
|---|---|---|
| A. 監視中に毎分の状態を記録 | `MonitorExtension` で毎秒の犬検出と画素の動きから1分ごとの状態を決めて SQLite に残す | **採用**。記録が安く欠けずに続き、今ある犬検出を使える。過去分はさかのぼれない |
| B. 低いコマ数の映像を常時保存して後で解析 | 判定を後から直して再解析できる | 不採用。容量が大きく、室内の映像を常に残すことになる |
| C. 犬検出なしで画面全体の動きだけで判定 | 軽い | 不採用。犬がサークル内にいるか分からず「映らない＝起きている」を扱えない |
| 保存済み動画から割り出す | — | 不採用。夜通しの映像がない |

## 設計

### 1分ごとの状態

1分（ローカル時刻の分の区切り）ごとに次のいずれかを1つ記録する。

| 状態 | 意味 | 1日の睡眠時間への扱い |
|---|---|---|
| `asleep` | サークル内で静止が続いている | 睡眠として数える |
| `awake` | サークル内で動いている、または静止がまだ短い | 起きている |
| `absent` | 犬が映っていない（サークルの外） | 起きている |
| `unknown` | 監視が動いていない、映像が途切れた、検出に失敗した | 記録なし（灰色）。合計に含めず、記録できた割合を併せて示す |

- 1分の中で状態が混ざったときは、秒数の多いほうを採る。観測できた秒数が1分の半分に満たなければ `unknown`。
- 監視が動いていない時間は行がないので、画面では行がない分を `unknown` として扱う。

### 睡眠の判定（我々の判断。しきい値は設定で調整できる）

毎秒（`dog.fps` の検出結果を使う）、次を求める。

1. **サークル内にいるか**: 行動マップの床面（`activity-layout.json`）の多角形の中に犬の枠の中心があるか。所有者の床面は寝る場所（トレーや端）まで覆っていると確認済み。床面が登録されていないときは、画面のどこかで犬が検出されたかで代える。
2. **静止しているか**: 前回の枠との中心の移動が枠の大きさに対して小さく（既定は枠の対角の 10% 未満）、かつ枠の中の画素の変化（縮小した灰色画像のフレーム間差分で、しきい値を超える画素の割合）が小さいこと。夜に赤外線の白黒映像になっても同じ計算で動く。
3. **検出が外れたとき（安全側の規則）**: 夜や丸まった姿勢で犬検出がどのくらい当たるかは分かっていない（所有者に確認済み）。「検出なし＝外にいる」とすると、検出が外れた夜を丸ごと「起きていた」と数えてしまう。そこで、犬の居場所は「出ていった証拠」があるまで保つ。
   - 直前までサークル内にいて、検出が外れても床面の中に画素の動きがなければ、直前の状態（静止なら静止の継続）を保つ。
   - 検出が外れ、その直前に床面の中で動き（特に床面の縁に向かう動き）があれば、出ていったとみなして `absent` にする。
   - 監視の開始直後や接続の再開直後など、直前の居場所が分からないまま検出がなく、床面にも動きがないときは、`absent` ではなく `unknown` にする。床面に動きがあるのに検出がないときも `unknown` にする（我々の判断）。
   - 犬が実際に外にいて床面が空のまま静かなときは、出ていったときの動きで `absent` になっているので、この規則で `unknown` が増えるのは居場所が分からないときだけになる。
4. **検出の当たり具合の記録**: 規則の妥当性を運用で確かめられるよう、1時間ごとに「サークル内にいるとみなした秒数のうち、犬検出が当たった秒数」を `sleep_minutes` とは別に記録し、GUI の草のマスの詳細に出す（我々の判断）。夜に当たる割合が低いと分かれば、しきい値や規則を見直す。

静止が `sleep.still_minutes`（既定5分）続いたら、静止の始まりまでさかのぼって `asleep` にする。静止が途切れたら `awake` に戻す。短い身じろぎ（`sleep.stir_seconds`、既定10秒以内の動き）は静止を途切れさせない。

排泄は1〜2分で終わるので、5分の静止の条件で多くは除ける。トレーの上で長く静止していれば、トレーの上でも睡眠として数える。

### 記録の保存

- `events.sqlite3` に `sleep_minutes` テーブルを足す（`records/database.py` の `MIGRATIONS` の末尾に追加）。列は `minute`（UTC の ISO 8601、分の始まり、主キー）、`state`、`observed_seconds`。体調の記録としてバックアップに含めたいので、行動マップの `activity.sqlite3` ではなく `events.sqlite3` に置く（我々の判断）。バックアップの `ALLOWED`・`SECRET_TABLES` は、テーブルを足しても変更不要なことを確かめる。
- 「静止の始まりまでさかのぼる」ので、記録は確定した分だけを書く。判定中の分はメモリーに持ち、確定したら書く。監視の終了時には、判定中の分を `awake` として書く（我々の判断）。
- 保持期間は無期限（1日1,440行で、1年でも約53万行）。

### 監視への組み込み

- `features/sleep.py`（判定と記録）と、監視の拡張 `SleepExtension` を足す。`ActivityExtension` と同じく位置合わせ前の映像（`on_camera_frame`）を使い、接続の途切れで静止の判定を区切る（`unknown`）。
- 犬検出の推論は `DogObserver.predict` を共有し、行動マップと二重に推論しない仕組みにする（同じフレームの結果を使い回す。実装の詳細は builder に任せる）。
- 有効にする方法: 設定の `sleep.enabled`（既定は無効）と `run --sleep`。犬の検出（`dog.enabled`）が必要で、`config.check_monitor_features` で確かめる。設定項目は `config.SETTINGS` に足す（`sleep.enabled`、`sleep.still_minutes`、`sleep.stir_seconds`、`sleep.daytime`）。
- README の機能表に「任意」の機能として足す。

### GUI の画面

`/sleep` に「睡眠」の画面を足し、メインメニューに加える（`gui/navigation.py`）。一般ユーザーも見られる。

1. **草の画面（中心）**: 横＝日付（既定は直近4週間、28列）、縦＝時刻（0〜23時、24行）。1マス＝1時間で、色の濃さ＝その1時間に寝ていた分数（0、1〜15、16〜30、31〜45、46〜60 分の5段階）。`unknown` が半分以上のマスは灰色の斜線などで「記録なし」と分かるようにする。マスに乗せると日付・時刻・睡眠の分数・記録できた分数を出す（`title` 属性で十分。JavaScript を使うなら `gui/static/`）。
2. **日ごとの合計の行**: 草の下に、各日の睡眠時間の合計と、記録できた割合を出す。記録できた割合が低い日（既定 80% 未満）は値に「参考」の印を付ける。
3. **日中の睡眠**: 設定の `sleep.daytime`（既定 `09:00-18:00`、既定値は我々の判断）の時間帯の睡眠の合計を日ごとに出す。休日も含め毎日同じ時間帯で数える（所有者に確認済み）。帰宅後に遊ぶ量の目安に使う。
4. **いつもとの差**: 直近7日の1日あたりの平均を、その前の4週間の平均と比べて、差（時間と%）を示す。記録できた割合が低い日は平均から除く。

色は `style.css` の変数で定義し、ライト・ダークの両方で読めるようにする。HTML は Jinja2 のテンプレートで作り、値の整形は Python 側（`gui/sleep_page.py`）で行う。期間は `?days=28` などで切り替えられるようにする（7・28・91日）。

### テスト

- 判定のロジックは、偽の時計・人工の枠・NumPy の人工画像で、静止5分で `asleep` になること、身じろぎで途切れないこと、検出が外れても動きがなければ寝続けること、外れる直前に動きがあれば `absent` になること、居場所が分からないまま検出も動きもなければ `unknown` になること、接続の途切れで `unknown` になることを確かめる。
- 移行処理は `tests/test_database.py` で古いスキーマから移せることを確かめる。
- GUI は人工の記録から画面を作り、集計の値とエスケープを確かめる（`tests/test_gui_escaping.py` に加える）。

## builder に任せること

- 静止の判定のしきい値の細かい値（画素の差分のしきい値、縮小の大きさ）。人工画像のテストで妥当な値を選び、定数として名前を付ける。
- 行動マップと睡眠の記録で推論の結果を共有する方法。
- 草のマスの見た目の細部（大きさ、間隔、凡例の配置）。添付の GitHub のグラフに近い見た目にする。
